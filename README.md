# ECO Pulse CA

An open, station-level PM2.5 benchmark for Central Asia (Uzbekistan, Kazakhstan, Kyrgyzstan,
Tajikistan, Turkmenistan), with pre-registered spatial and temporal splits that are frozen
and checksummed.

I did not build this to win at a model. In my opinion what this region is actually missing
is a fair way to compare models, because right now every paper picks its own stations, its
own years and its own split, so the numbers cannot be put next to each other. So that is
what this repository is: frozen splits, a QC pipeline where every decision is written down,
and a baseline ladder that the next method has to beat on exactly the same rows.

> **Status:** benchmark **v1.1.0**, frozen and checksummed. The manuscript is prepared as a
> *Scientific Data* Data Descriptor (`paper/sdata_descriptor.md`). Every number reported in
> it is regenerated by one command and comes out byte-identical across runs.
>
> **Dataset DOI:** [10.5281/zenodo.21930669](https://doi.org/10.5281/zenodo.21930669)
> (version 1.1.0, CC BY 4.0, deposited 2026-08-14). Cite the version DOI and the checksum,
> not the branch head.

## What this is, in one paragraph

Daily PM2.5 for **7 instruments across 6 Central Asian cities** (Almaty, Ashgabat, Bishkek,
Dushanbe, Khujand, Tashkent), 247,075 retained hourly observations, quality-controlled by
seven rules that were written down before anyone looked at the data. Five of the instruments
are US diplomatic-post reference monitors and two are Clarity low-cost sensors in Khujand.
Each station is paired with satellite retrievals, CAMS forecasts, ERA5 meteorology and
static geography, and every predictor carries an acquisition latency that was *measured*,
not copied from documentation. On top of that the evaluation splits are frozen and hashed
(blocked-temporal with a 240 h purge, and leave-city-out over 6 folds), so two methods can be
compared on identical terms.

## Data: what is and is not here

| | where | licence |
|---|---|---|
| **Frozen split definitions + checksums** | `benchmark/splits/` | CC BY 4.0 |
| **Reference result tables** | `paper/tables/` | CC BY 4.0 |
| **Code** | everything else | MIT |
| **Raw PM2.5 observations** | **not redistributed** | OpenAQ providers' own terms |

The observations are not redistributed here because the per-provider licence terms are not
the same for every contributor, and four of the ten source feeds carry no licence record at
all. `data/MANIFEST.md` has the full per-feed matrix with what we could and could not
establish, plus the two commands that rebuild the derived panel from the original archive
with an OpenAQ key.

That being said, **verifying the benchmark needs no credentials and no rebuild.**
`sha256sum -c benchmark/splits/splits.sha256` is enough, and the whole test suite runs
offline.

## Scoring a method on this benchmark

1. Read `benchmark/splits/splits.json`. It is self-contained: stations, temporal blocks,
   folds.
2. Train only on the rows a fold permits. The held-out city must not appear anywhere,
   including through a neighbour feature or a bias correction that was estimated on it.
3. Predict the daily target: local-calendar daily mean PM2.5, built from at least 18 hourly
   observations.
4. Report **per city**, with the spread over the 5 declared seeds (0 to 4).
5. Compare against `paper/tables/t3_06_task_n_baselines_daily.csv`, which is scored on the
   same rows at the same resolution.

## Quickstart

```bash
python scripts/setup_env.py
```

That builds the pinned Python 3.12 environment in `.venv` and installs the project. It works
with or without [`uv`](https://docs.astral.sh/uv/). If `uv` is on PATH it gets used (and can
download a 3.12 for you), otherwise the script finds a usable interpreter and falls back to
`venv` and `pip`. One thing it does deliberately: it **runs** each candidate interpreter
instead of trusting the version metadata, because on my own Windows machine the `py`
launcher advertised a 3.12 that would not actually start. Re-running is safe, a healthy
`.venv` is reused rather than rebuilt. Pass `--force` if you want it recreated.

Once the environment exists, `make setup` and `python tasks.py setup` do the same thing.

<details>
<summary><b>Windows: if <code>python tasks.py …</code> fails with exit 103</b></summary>

The Microsoft Store build of Python runs in a sandbox that cannot see `%APPDATA%\Roaming`.
If your 3.12 lives there, which is where `uv` puts it, then any subprocess into `.venv` dies
with `No Python at '…'`. The environment is fine, the launcher just cannot reach it.
`tasks.py` detects this case and prints the fix. Quickest one:

```bash
.venv\Scripts\python.exe tasks.py test
```
</details>

Run the tests. No credentials needed, everything runs against committed fixtures:

```bash
python -m pytest
```

## What a reviewer can do, and what needs a key

I want to be precise about this, because "one command reproduces everything" is only true
once the ground-truth panel already exists on your machine.

**Without any credentials, from a clean clone:**

| Goal | Command |
|---|---|
| Verify the frozen benchmark | `cd benchmark/splits && sha256sum -c splits.sha256` |
| Run the full test suite (582 tests, offline fixtures) | `python tasks.py test` |
| Lint and type-check | `python tasks.py lint && python tasks.py typecheck` |

The splits **are** the benchmark, and they are committed, so verifying them takes no rebuild
and no key.

**To regenerate the numbers from source**, the derived panel has to be built first. It is not
committed, for the licence reasons above. With an `OPENAQ_API_KEY` in `.env` (see
[`REGISTRATION.md`](REGISTRATION.md)):

```bash
python -m ecopulse_ca.ingest.openaq --out data/interim/station_census.csv
python scripts/pull_panel.py
```

Then one command rebuilds every reported number end to end:

```bash
make reproduce
```

`python tasks.py paper` sits on the same side of that line. It rebuilds every table and
re-renders both documents, and its first step reads the built panel, so it does not run from
a clean clone either.

Where `make` is missing, `python tasks.py reproduce` is the same chain. It runs lint,
typecheck, tests, splits (frozen and hash-verified *before* any model sees data), baselines
over 5 seeds, tables, manuscript render, stitch, and it stops at the first failure. If you
try it without the panel it fails with instructions instead of a bare traceback.

`make reproduce` is idempotent. Running it again leaves the working tree clean, including
`splits.sha256`, whose freeze timestamp is preserved when the hash has not changed.

On Windows `python tasks.py <target>` runs every Makefile target. The Makefile delegates to
`tasks.py`, so the two cannot drift into issuing different commands, and there is a test that
asserts the delegation still holds.

## The rules this repo enforces mechanically

These are the failure modes that make air quality ML results untrustworthy. Each one is a
test rather than a convention, because a convention does not fail the build.

| Rule | Enforced by |
|---|---|
| **No random splits, ever** | `tests/test_no_random_splits.py`, a static scan of `src/`. Air quality data is autocorrelated in space and in time, so a shuffle puts the same station and often the same hour on both sides of the split. |
| **Splits are immutable once frozen** | `benchmark/splits/splits.sha256`, hash-checked. If a frozen city turns out to have poor predictor coverage, that gets *reported*, never fixed by re-freezing. |
| **No target leakage** | Same-timestamp co-located PM2.5 is barred, and every feature's provenance is traced. |
| **No lookahead in operational features** | ERA5 and CAMS reanalysis do not exist at prediction time. Results that use them are labelled reanalysis-oracle ablations, never deployed numbers. |
| **Nothing dropped silently** | Every QC rule reports its **n-effect** into [`data/DECISIONS.md`](data/DECISIONS.md). |
| **Timezones validated against physics** | Diurnal-shape cross-correlation instead of metadata, including detection of offsets that change mid-record. |
| **Every number is traceable** | `paper/numbers.json` is extracted from the banked CSVs and substituted into the prose at render time. `tests/test_manuscript_numbers.py` enforces that chain end to end, and `tests/test_table_provenance.py` fails if a published table has no producer inside `make reproduce`. |

## Two tasks, never mixed in one table

- **Task F, forecasting.** At a monitored station, predict PM2.5 at t+24/48/72 h. Ladder:
  persistence, then diurnal persistence, then climatology, then ridge, then LightGBM.
- **Task N, nowcasting.** Estimate PM2.5 in a held-out city with **zero** local labels.
  Ladder: nearest-monitor, then IDW, then ordinary kriging, then satellite models.

Task N's interpolation rungs are the comparison reviewers actually want against a satellite
model. Does it beat just interpolating from nearby monitors? That question gets skipped a
lot, so those rungs are built first here.

## Regional context that shapes the design

All of this is load-bearing, not background. It comes from the OpenAQ 2024 data landscape
report and the Phase 0 review.

- **Turkmenistan has no national air quality monitoring at all.** Ashgabat enters only
  through the US Embassy monitor.
- **Kazakhstan shares its data only with people inside Kazakhstan.** A benchmark that a third
  party cannot reconstruct is not open, so Kazakh stations enter only through a path that is
  independently retrievable.
- **Only Kyrgyzstan shares fully openly.** Tajikistan started sharing in 2024.
- **The US Embassy network is the spine of this benchmark.** It is the only consistent
  multi-country reference in the region.
- **MAIAC AOD missingness correlates with the target.** Retrievals fail during dust storms,
  snow and heavy cloud, which are exactly the extreme episodes. Rows with missing AOD are
  modelled and never dropped, because dropping them conditions the whole thing on "retrieval
  succeeded" and biases the results toward calm, clear, low-concentration days.

## What this benchmark cannot tell you

Worth reading before you report anything from it.

- **The reference network no longer exists.** Five of the ten source feeds stop on
  2025-03-04, when the StateAir publication channel closed, and after co-published feeds are
  merged, 2 of the 7 stations (8881 and Bishkek) end there. Nothing here speaks to current
  conditions.
- **Bishkek's 2024 ground truth depends on who published it.** Its two feeds agree on only
  11.1% of overlapping hours inside the test block. Per-hour provenance is kept so results
  can be recomputed against either publisher.
- **Leave-station-out covers one city.** Only Khujand holds two instruments, so that
  protocol has 2 folds and the other five cities are listed as ineligible. It is a stated
  coverage gap, not an absence I hoped nobody would notice.
- **Kazakhstan contributes one city.** Astana failed the completeness rule at 42.8% against
  a 60% floor, so the largest country in the region is represented by Almaty alone.
- **Timezone correctness is unverifiable at five of the six cities.** The within-city check
  needs two instruments in one city, and after the Dushanbe merge only Khujand has that. A
  constant lifelong offset at Almaty, Tashkent, Bishkek, Ashgabat or Dushanbe would not be
  caught by anything in this suite.
